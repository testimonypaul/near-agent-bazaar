# Architecture

## Demo runtime

The React client loads a versioned world snapshot from browser local storage. The market engine is deterministic in its rules and uses bounded randomness for market shocks. Each merchant has a distinct policy:

- **Max — opportunist:** releases inventory into high-demand markets and watches price gaps.
- **Luna — collector:** prioritizes rare inventory and responds to crystal demand.
- **Rex — industrialist:** focuses on broad supply and regular restocking.

A market cycle updates supply/demand, runs each merchant policy, and appends an activity record. Player trades enforce stock, treasury and balance constraints.

## Trust boundaries

The current browser simulation is not a trusted economic environment. Users can modify local storage and client code. Demo credits and items have no real-world value. Do not use this state to distribute prizes or settle real payments.

## NEAR contract boundary

The Rust contract is a testnet-oriented inventory ledger scaffold. It supports merchant registration, native NEAR treasury deposits, owner inventory seeding and authorized inventory transfers between registered merchant accounts.

It does **not** yet:
- implement NEP-245 multi-token standards;
- custody or transfer NEP-141 fungible tokens;
- connect browser merchant identities to the local simulation;
- provide an AI inference runtime or prove that an action was generated by an AI model.

These are explicit next milestones, not completed features.

## Next production milestones

1. Add a NEAR Wallet Selector adapter and read-only contract calls.
2. Replace owner-seeded inventory with a properly governed mint/issuance model.
3. Add signed trade intents with nonce, expiry, slippage and replay protection.
4. Move agent policy execution to a server/TEE or verifiable execution environment.
5. Add event indexing and reconcile UI state against finalized chain receipts.
